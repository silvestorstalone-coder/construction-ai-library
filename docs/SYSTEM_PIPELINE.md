# SYSTEM_PIPELINE.md

## Архитектура AI pipeline

### Основные компоненты

AI pipeline состоит из следующих основных компонентов:

1. **Data Ingestion (Приём данных)**: модуль для сбора и предварительной обработки данных, необходимых для обучения и тестирования моделей.
2. **Feature Engineering (Разработка признаков)**: модуль для создания и преобразования признаков, которые будут использоваться моделями.
3. **Model Training (Обучение моделей)**: модуль для обучения моделей на основе подготовленных данных.
4. **Model Evaluation (Оценка моделей)**: модуль для оценки производительности моделей с использованием метрик качества.
5. **Deployment (Развёртывание)**: модуль для развёртывания обученных моделей в продуктивной среде.
6. **Monitoring and Logging (Мониторинг и логирование)**: модуль для мониторинга работы моделей и сбора логов.

### Взаимодействие компонентов

Компоненты взаимодействуют между собой через API и файловую систему. Данные передаются между модулями в формате JSON или CSV.

## GitHub Actions

Для автоматизации CI/CD процесса используется GitHub Actions. GitHub Actions позволяет создавать рабочие процессы, которые выполняются при определённых событиях, таких как коммиты в репозиторий или создание новых веток.

### Пример рабочего процесса

1. **Pull Request (PR)**: при создании PR запускается проверка кода и тестирование.
2. **Commit**: при каждом коммите в ветку `main` запускается сборка и тестирование.
3. **Release**: при создании нового тега запускается сборка и развёртывание модели в продуктивной среде.

## YandexGPT integration

Для интеграции с YandexGPT используется API YandexGPT. API позволяет отправлять запросы к модели и получать ответы в формате JSON.

### Пример использования

1. **Feature Extraction (Извлечение признаков)**: модуль Feature Engineering отправляет запросы к API YandexGPT для извлечения признаков из текста.
2. **Model Training**: модуль Model Training использует извлечённые признаки для обучения модели.

## Структура модулей

Модули организованы в виде директорий и файлов. Каждый модуль содержит следующие файлы:

- `main.py`: основной файл модуля, который содержит логику работы.
- `config.py`: файл с настройками модуля.
- `tests.py`: файл с тестами для модуля.

Модули могут быть разделены на подмодули для более детальной организации кода.

## CI/CD поток

CI/CD поток включает в себя следующие этапы:

1. **Code Review (Проверка кода)**: код проверяется на соответствие стандартам качества.
2. **Build (Сборка)**: код собирается в исполняемый файл или контейнер.
3. **Test (Тестирование)**: модуль тестируется на соответствие требованиям.
4. **Deploy (Развёртывание)**: обученная модель разворачивается в продуктивной среде.
5. **Monitor (Мониторинг)**: работа модели мониторится и логируются результаты.

Каждый этап может быть настроен с использованием GitHub Actions.
