# SYSTEM_PIPELINE.md

## Архитектура AI pipeline

### Основные компоненты

1. **Data Ingestion (Приём данных)**: модуль для сбора и предварительной обработки данных, необходимых для обучения и тестирования моделей.
2. **Feature Engineering (Разработка признаков)**: создание и преобразование признаков для улучшения качества моделей.
3. **Model Training (Обучение моделей)**: модуль для обучения AI-моделей с использованием выбранных алгоритмов и фреймворков.
4. **Model Evaluation (Оценка моделей)**: оценка производительности моделей на основе заранее определённых метрик.
5. **Deployment (Деплоймент)**: развёртывание обученных моделей в продуктивной среде.
6. **Monitoring and Logging (Мониторинг и логирование)**: отслеживание работы моделей и сбор логов для анализа.

### Интеграции

- **GitHub Actions**: используется для автоматизации CI/CD процессов, включая сборку, тестирование и деплоймент.
- **YandexGPT integration**: интеграция с YandexGPT для генерации текста и улучшения качества данных для обучения моделей.

## GitHub Actions

GitHub Actions позволяет автоматизировать рабочие процессы в репозитории. Основные шаги в CI/CD потоке:

1. **Pull Request (PR) Trigger**: запуск действий при создании или обновлении PR.
2. **Workflow Definition**: определение шагов для сборки, тестирования и деплоймента.
3. **Actions**: использование предопределённых или пользовательских действий для выполнения задач.
4. **Caching**: кэширование результатов для ускорения последующих сборок.

## Структура модулей

- **data_ingestion**: модуль для сбора и предварительной обработки данных.
- **feature_engineering**: модуль для разработки признаков.
- **model_training**: модуль для обучения моделей.
- **model_evaluation**: модуль для оценки моделей.
- **deployment**: модуль для развёртывания моделей.
- **monitoring_logging**: модуль для мониторинга и логирования.

## CI/CD поток

1. **Code Changes (Изменения в коде)**: при изменении кода в репозитории, GitHub Actions запускает соответствующий workflow.
2. **Build (Сборка)**: сборка проекта с использованием необходимых инструментов и зависимостей.
3. **Test (Тестирование)**: выполнение тестов для проверки корректности работы кода.
4. **Deploy (Деплоймент)**: развёртывание изменений в продуктивной среде.
5. **Monitor (Мониторинг)**: отслеживание работы системы после деплоймента.

Каждый шаг в CI/CD потоке может быть настроен и оптимизирован для обеспечения непрерывной интеграции и доставки.
