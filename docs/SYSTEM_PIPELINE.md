# SYSTEM_PIPELINE.md

## Архитектура AI pipeline

### Основные компоненты

1. **Data Ingestion (Приём данных)**: модуль для сбора и предварительной обработки данных, необходимых для обучения и тестирования моделей.
2. **Feature Engineering (Разработка признаков)**: создание и преобразование признаков для улучшения качества моделей.
3. **Model Training (Обучение моделей)**: модуль для обучения моделей на основе собранных данных.
4. **Model Evaluation (Оценка моделей)**: оценка производительности моделей с использованием различных метрик.
5. **Deployment (Развёртывание)**: размещение обученных моделей в среде для использования.
6. **Monitoring and Logging (Мониторинг и логирование)**: отслеживание работы моделей и сбор логов для анализа.

### Взаимодействие компонентов

Компоненты взаимодействуют друг с другом через API и очереди сообщений, обеспечивая поток данных и выполнение задач в определённой последовательности.

## GitHub Actions

GitHub Actions используется для автоматизации CI/CD процессов. Основные этапы:

1. **Pull Request (PR) Trigger**: запуск действий при создании или обновлении PR.
2. **Commit Trigger**: запуск действий при коммитах в репозиторий.
3. **Workflow Definition**: определение шагов для выполнения в рамках workflow.
4. **Actions**: конкретные действия, выполняемые в рамках workflow (например, тестирование, сборка, развёртывание).

### Пример workflow

```yaml
name: CI/CD Pipeline
on:
  push:
    branches:
      - main
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v2
      - name: Run tests
        run: |
          pytest
      - name: Build Docker image
        run: |
          docker build . -t my-image
      - name: Push Docker image
        uses: docker/build-push-action@v2
        with:
          push: true
          tags: my-image:latest
```

## YandexGPT integration

YandexGPT интегрируется в pipeline для генерации текста и улучшения качества данных. Основные шаги:

1. **API Call**: вызов API YandexGPT для получения результатов генерации.
2. **Integration Point**: точка интеграции с другими компонентами pipeline.
3. **Data Processing**: обработка результатов генерации и интеграция с другими данными.

### Пример интеграции

1. **Предварительная обработка данных**: данные передаются в YandexGPT для генерации описаний или комментариев.
2. **Интеграция с Feature Engineering**: результаты генерации интегрируются с другими признаками для улучшения моделей.
3. **Использование в Model Training**: данные, полученные от YandexGPT, используются для обучения моделей.

## Структура модулей

- **data_ingestion**: модуль для сбора и предварительной обработки данных.
- **feature_engineering**: модуль для разработки признаков.
- **model_training**: модуль для обучения моделей.
- **model_evaluation**: модуль для оценки моделей.
- **deployment**: модуль для развёртывания моделей.
- **monitoring_logging**: модуль для мониторинга и логирования.

## CI/CD поток

1. **Code Changes (Изменения в коде)**: при изменении кода в репозитории запускается workflow.
2. **Tests (Тесты)**: выполняются тесты для проверки корректности кода.
3. **Build (Сборка)**: собирается Docker образ с приложением.
4. **Push (Развёртывание)**: образ Docker публикуется в реестре и развёртывается в среде.
5. **Monitoring (Мониторинг)**: после развёртывания модели отслеживаются и логируются для анализа.
