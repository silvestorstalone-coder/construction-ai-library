# SYSTEM_PIPELINE.md

## Архитектура AI pipeline

### Основные компоненты

AI pipeline состоит из следующих основных компонентов:

1. **Data Ingestion (Сбор данных)**: модуль для сбора и предварительной обработки данных, необходимых для обучения и тестирования моделей.
2. **Feature Engineering (Разработка признаков)**: модуль для создания и преобразования признаков, которые будут использоваться моделями.
3. **Model Training (Обучение моделей)**: модуль для обучения моделей на основе собранных данных.
4. **Model Evaluation (Оценка моделей)**: модуль для оценки производительности моделей и выбора наилучших.
5. **Deployment (Развёртывание)**: модуль для развёртывания моделей в продуктивной среде.
6. **Monitoring and Maintenance (Мониторинг и обслуживание)**: модуль для мониторинга производительности моделей и их обслуживания.

### Взаимодействие компонентов

Компоненты взаимодействуют друг с другом через API и файловую систему. Данные передаются между модулями в формате JSON или CSV.

## GitHub Actions

Для автоматизации CI/CD потока используется GitHub Actions. GitHub Actions позволяет создавать рабочие процессы, которые выполняются при определённых событиях, таких как создание ветки, открытие пул-реквеста или коммит в репозиторий.

### Пример рабочего процесса

1. **Pull Request (PR) открыт**: при открытии PR запускается рабочий процесс, который выполняет следующие действия:
   - Проверяет код на соответствие стандартам оформления.
   - Запускает тесты.
   - Собирает артефакты (например, модели и скрипты).

2. **Коммит в ветку `main`**: при коммите в ветку `main` запускается рабочий процесс, который выполняет следующие действия:
   - Собирает и тестирует код.
   - Развёртывает модели в тестовой среде.
   - Отправляет уведомление о развёртывании в Slack.

## YandexGPT integration

Для интеграции с YandexGPT используется API YandexGPT. API позволяет отправлять запросы к модели и получать ответы в формате JSON.

### Пример использования

1. **Сбор данных**: данные собираются и преобразуются в формат, который может быть использован моделью YandexGPT.
2. **Запрос к модели**: модель YandexGPT используется для генерации текста на основе собранных данных.
3. **Обработка ответа**: ответ модели обрабатывается и сохраняется в базе данных или файловой системе.

## Структура модулей

Модули организованы в виде директорий и файлов. Каждый модуль содержит следующие файлы:

- `main.py`: основной файл модуля, который содержит логику работы модуля.
- `config.json`: файл конфигурации модуля, который содержит параметры и настройки.
- `tests`: директория с тестами для модуля.

## CI/CD поток

CI/CD поток включает в себя следующие этапы:

1. **Сборка (Build)**: код собирается в артефакты, которые могут быть развёрнуты в среде.
2. **Тестирование (Test)**: артефакты тестируются на соответствие требованиям.
3. **Развёртывание (Deploy)**: артефакты развёртываются в тестовой или продуктивной среде.
4. **Мониторинг (Monitor)**: производительность развёрнутых артефактов мониторится и анализируется.

Каждый этап выполняется в отдельном рабочем процессе GitHub Actions. Рабочие процессы могут быть связаны друг с другом для создания потока CI/CD.
