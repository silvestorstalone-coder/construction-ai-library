# SYSTEM_PIPELINE.md

## Архитектура AI pipeline

### Основные компоненты

AI pipeline состоит из следующих основных компонентов:

1. **Data Ingestion (Сбор данных)**: модуль для сбора и предварительной обработки данных, необходимых для обучения и тестирования моделей.
2. **Feature Engineering (Разработка признаков)**: модуль для создания и преобразования признаков, которые будут использоваться моделями.
3. **Model Training (Обучение моделей)**: модуль для обучения моделей на основе собранных данных.
4. **Model Evaluation (Оценка моделей)**: модуль для оценки производительности моделей на тестовых данных.
5. **Deployment (Развёртывание)**: модуль для развёртывания обученных моделей в продуктивной среде.
6. **Monitoring and Logging (Мониторинг и логирование)**: модуль для мониторинга работы моделей и сбора логов.

### Взаимодействие компонентов

Компоненты взаимодействуют друг с другом через API и файловую систему. Данные передаются между модулями в формате JSON или CSV.

## GitHub Actions

Для автоматизации CI/CD процесса используется GitHub Actions. GitHub Actions позволяет создавать рабочие процессы, которые выполняются при определённых событиях (например, при создании ветки или пуше изменений в репозиторий).

### Пример рабочего процесса

1. **Pull Request (PR) created (Создание PR)**: при создании PR запускается рабочий процесс, который выполняет следующие действия:
   - Проверка кода на соответствие стандартам (например, с помощью `eslint` или `flake8`).
   - Запуск тестов (например, `pytest` или `unittest`).
   - Сборка и тестирование модели (например, с помощью `docker`).

2. **Push to main branch (Пуш в основную ветку)**: при пуше изменений в основную ветку запускается рабочий процесс, который выполняет следующие действия:
   - Сборка и тестирование модели.
   - Развёртывание модели в тестовой среде.
   - Мониторинг работы модели.

## YandexGPT integration

Для интеграции с YandexGPT используется API YandexGPT. API позволяет отправлять запросы к модели и получать ответы в формате JSON.

### Пример использования

1. **Сбор данных**: данные, необходимые для генерации текста с помощью YandexGPT, собираются в модуле Data Ingestion.
2. **Генерация текста**: модуль Feature Engineering преобразует данные в формат, который можно передать в API YandexGPT. Затем модуль Model Training отправляет запрос к API и получает ответ.
3. **Оценка качества текста**: модуль Model Evaluation оценивает качество сгенерированного текста.

## Структура модулей

Модули организованы в виде директорий в репозитории. Каждый модуль содержит следующие файлы:

- `main.py`: основной файл модуля, который содержит код для выполнения основных функций модуля.
- `config.py`: файл конфигурации модуля, который содержит настройки и параметры.
- `tests.py`: файл с тестами для модуля.

## CI/CD поток

CI/CD поток включает в себя следующие этапы:

1. **Code review (Код-ревью)**: код проходит код-ревью перед тем, как изменения будут объединены в основную ветку.
2. **Build and test (Сборка и тестирование)**: после успешного код-ревью запускается сборка и тестирование модели.
3. **Deploy to test environment (Развёртывание в тестовую среду)**: обученная модель развёртывается в тестовой среде для проверки её работы.
4. **Monitor and log (Мониторинг и логирование)**: работа модели мониторится, а логи собираются для дальнейшего анализа.
5. **Deploy to production (Развёртывание в продуктивную среду)**: после успешного тестирования модель развёртывается в продуктивной среде.
