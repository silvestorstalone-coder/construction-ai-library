# SYSTEM_PIPELINE.md

## Архитектура AI pipeline

### Основные компоненты

1. **Data Ingestion (Приём данных)**: модуль для сбора и предварительной обработки данных, необходимых для обучения и тестирования моделей.
2. **Feature Engineering (Разработка признаков)**: создание и преобразование признаков для улучшения качества моделей.
3. **Model Training (Обучение моделей)**: модуль для обучения AI-моделей на подготовленных данных.
4. **Model Evaluation (Оценка моделей)**: оценка производительности моделей с использованием метрик качества.
5. **Deployment (Развёртывание)**: модуль для развёртывания обученных моделей в продуктивной среде.
6. **Monitoring and Logging (Мониторинг и логирование)**: отслеживание работы системы и сбор логов для анализа.

### Взаимодействие компонентов

Компоненты взаимодействуют между собой через API и очереди сообщений, обеспечивая поток данных и выполнение задач в определённой последовательности.

## GitHub Actions

Для автоматизации CI/CD процесса используется GitHub Actions. Основные этапы:

1. **Pull Request (PR)**: при создании PR запускается автоматизированный процесс проверки кода.
2. **Code Quality Checks**: выполнение статического анализа кода и тестов.
3. **Build**: сборка проекта.
4. **Test**: запуск тестов для проверки функциональности.
5. **Deploy**: развёртывание изменений в тестовой или продуктивной среде.

## YandexGPT integration

Интеграция с YandexGPT осуществляется через API для генерации текста и обработки естественного языка. Модуль Feature Engineering использует результаты работы YandexGPT для обогащения данных и улучшения качества моделей.

## Структура модулей

- **data_ingestion**: модуль для сбора и предварительной обработки данных.
- **feature_engineering**: модуль для разработки признаков.
- **model_training**: модуль для обучения моделей.
- **model_evaluation**: модуль для оценки моделей.
- **deployment**: модуль для развёртывания моделей.
- **monitoring_logging**: модуль для мониторинга и логирования.

## CI/CD поток

1. **Code Commit**: разработчик совершает изменения в коде и создаёт PR.
2. **GitHub Actions**: запускается автоматизированный процесс проверки и сборки кода.
3. **Tests**: выполняются тесты для проверки функциональности.
4. **Model Training**: если тесты пройдены, запускается обучение модели.
5. **Model Evaluation**: модель оценивается на основе метрик качества.
6. **Deployment**: если модель удовлетворяет требованиям, она развёртывается в тестовой или продуктивной среде.
7. **Monitoring**: после развёртывания модель мониторится для обеспечения стабильной работы.
