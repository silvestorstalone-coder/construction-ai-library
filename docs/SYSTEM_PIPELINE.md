# 🏗️ SYSTEM_PIPELINE.md: Архитектурный Эталон

> Этот файл определяет логику расчетов. Любое изменение кода должно соответствовать этим формулам.

## 1. Порядок обработки (Pipeline)
1. **Estimate** (Сбор данных) ➔ 2. **Technology** (Расчет трудозатрат) ➔ 3. **Finance** (Себестоимость) ➔ 4. **Schedule** (Сроки).

## 2. Логика модулей

### 📦 Модуль TECHNOLOGY (Трудозатраты)
- **Источник**: Ищет совпадения названий работ из `estimateResult` в базе `NORMS_DATABASE.md`.
- **Формула**: `Человеко-часы = Объём_из_сметы * Норма_времени_из_базы`.
- **Инструментарий**: Определяет тип техники/инструмента на основе ключа `equipment` в базе норм.

### 📦 Модуль FINANCE (Экономика)
- **Материалы (materialsCost)**: Сумма `(quantity * price)` для всех позиций из `estimateResult.totalWorksList`.
- **Труд (laborCost)**: `Итого_чел_часов * Ставка_часа (500 руб)`.
- **Техника (equipmentCost)**: Расход топлива или аренда, если указано в Technology.
- **Итого (totalCost)**: `(Materials + Labor + Equipment) * 1.15` (15% накладные расходы).

### 📦 Модуль SCHEDULE (График)
- **Срок выполнения (days)**: `Человеко-часы / (Кол-во рабочих * 8 часов)`.
- **Критический путь**: Последовательное сложение этапов из `estimateResult.stages`.

## 3. Правила написания кода для ИИ
- **Никаких заглушек**: Переменные не должны быть равны 0, если данные доступны в `estimateResult`.
- **Отказоустойчивость**: Если работа не найдена в базе норм, использовать среднее значение 0.5 чел-час/ед.
- **Логирование**: Обязательно вызывать `logInfo` при начале и конце расчета.
